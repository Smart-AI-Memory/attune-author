# Preamble

A preamble is a context-sensitive one-liner that introduces a workflow skill. Instead of every skill opening with the same static text, the preamble system lets you look up a short, feature-specific lead-in at render time.

## How it works

The module exposes two lookup functions, both keyed by feature name:

- **`get_preamble(feature_name, help_dir=None)`** returns the one-liner preamble for a feature, or `None` if no preamble exists for that name. Pass `help_dir` to look up preambles from a specific help directory instead of the default location.
- **`get_related_preambles(feature_name, help_dir=None, max_results=3)`** returns preambles for features that share tags with the given feature, as a list of dictionaries. Use `max_results` to control how many related entries you get back (the default is 3).

The mental model: `get_preamble()` answers "what should I say about *this* feature?", while `get_related_preambles()` answers "what nearby features might the user also care about?" Together they let a skill open with a relevant sentence and point sideways to related topics without hardcoding either.

## Connections to the rest of the codebase

Relatedness between features is determined by shared tags — the same tags that appear in template frontmatter (see the template design patterns concept). A feature tagged `[templates, help-system]` surfaces as related to other features carrying those tags.

Callers reach this feature through two public functions:

| Function | Purpose | File |
|----------|---------|------|
| `get_preamble()` | Look up the one-liner preamble for a feature | `src/attune_author/preamble.py` |
| `get_related_preambles()` | Look up preambles for features related by shared tags | `src/attune_author/preamble.py` |

You typically call `get_preamble()` first when rendering a skill's opening line, then optionally call `get_related_preambles()` to suggest adjacent features.
